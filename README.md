# rpi_ros2_motor_proxy

This Rust application provides a WebSocket server which accepts JSON commands for tank tracks (left/right in [-1..1]) and publishes them as ROS 2 Twist messages on the topic /cmd_vel. In other words, it’s a proxy between a WebSocket client (e.g. a SwiftUI app) and a ROS 2 robot node.

##Overview

ROS 2 Setup
Uses rclrs to create a node called motor_proxy.
Publishes geometry_msgs/msg/Twist messages on /cmd_vel.
WebSocket Server
Listens on 0.0.0.0:8081 for incoming connections.
Each client sends JSON, e.g. {"left": 0.5, "right": -0.8}.
The server converts that to a Twist (linear.x / angular.z) and publishes it.
Differential Drive Mapping
The code does a simple differential-drive formula in tracks_to_twist(left, right):
twist.linear.x = ((left + right)/2) * linear_scale
twist.angular.z = ((right - left)/2) * angular_scale
So the user can connect via WebSocket, send track speeds, and have them appear on the robot’s ROS 2 system as Twist commands.

## Dependencies

Rust (1.65+ recommended).
Tokio / futures / tokio-tungstenite for async WebSocket.
serde / serde_json for JSON parsing.
rclrs for ROS 2 integration in Rust.
geometry_msgs crate for the Twist message.
## Building

Ensure you have ROS 2 installed and configured for rclrs.
Clone or place this code in a cargo project.
Edit Cargo.toml to include needed crates:
[dependencies]
rclrs = "0.11.0"
tokio = { version = "1", features = ["rt-multi-thread", "macros"] }
tokio-tungstenite = "0.17"
futures-util = "0.3"
serde = { version = "1", features = ["derive"] }
serde_json = "1"
geometry_msgs = "<version>"
(Adjust versions as needed.)
Build:
cargo build --release
## Running

Source your ROS 2 environment:
source /opt/ros/<distro>/setup.bash
Run the binary:
./target/release/motor_proxy
It will:
Create a node named motor_proxy.
Start a WebSocket server on port 8081.
Spin a ROS loop in a separate thread, allowing publish() calls on /cmd_vel.
## Usage

## WebSocket Clients
Connect to ws://<your_pi_ip>:8081.
Send JSON messages of form:
{"left": 0.8, "right": -0.4}
which sets left=0.8 and right=-0.4 for track speeds in range [-1..1].
Robot Side
Another ROS 2 node (like your motor driver node) subscribes to /cmd_vel with message type Twist.
Each Twist is generated by the tracks_to_twist() function.
You can echo:
ros2 topic echo /cmd_vel
to see the messages in real time.
## Implementation Details

main()
Creates an rclrs context and node.
Spawns a thread calling spin_once(...) in a loop, so the node processes callbacks.
Sets up a TCP listener on 0.0.0.0:8081.
For each new client, calls handle_client(), which upgrades to WebSocket and reads text messages.
handle_client()
Repeatedly receives text frames.
Parses JSON into TrackCommand { left, right }.
Calls tracks_to_twist(left, right), publishes to /cmd_vel.
tracks_to_twist()
A simple differential-drive formula with a linear_scale and angular_scale.
For more advanced robotics logic, you’d adjust or replace this function.
